# Zig 0.17.1 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Move nullclaw from the pinned Zig 0.16.0 toolchain to Zig 0.17.1 while keeping `zig build -Doptimize=ReleaseSmall` and the full test suite green.

**Architecture:** Zig 0.17 removed `**` array repetition, `@cImport`, and several `std.Build`/stdlib APIs. The migration replaces those with small compatibility helpers, generated or hand-written C bindings, vendored websocket sources, and a version-pin sweep across docs/CI/Docker/flake.

**Tech Stack:** Zig 0.17.1, vendored SQLite 3.51.0, vendored websocket package, libpq, wasm3.

**Spec:** `AGENTS.md` §2.4, §7.6, §8; user request to migrate the repository to Zig 0.17.1.

## Global Constraints

- Toolchain: Zig **0.17.1** exactly.
- Release build target: `zig build -Doptimize=ReleaseSmall`.
- Full validation: `zig build test --summary all` with 0 failures and 0 leaks.
- No new runtime dependencies beyond the existing SQLite, websocket, libpq, and wasm3 surfaces.
- Keep secure-by-default behavior; no permission broadening.
- Keep all English and Chinese docs in sync.
- Do not commit secrets or personal data.

## Review Focus

- Any expression that previously used `a ** n` can no longer rely on implicit array-to-slice coercion; verify call sites compile.
- Hand-written libpq bindings must match the C ABI for `PQexecParams` and row accessors.
- Generated SQLite/wasm3 bindings must stay in sync with the pinned headers.
- Vendored websocket must remain deterministic and carry its upstream MIT license.
- Android cross-builds no longer have a build-script `--libc` check; rely on the compiler's own diagnostic.
